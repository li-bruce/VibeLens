## 对话结果如何理解

Python 测试采用驱动模式，Node 采用观察模式。两者都保留多个独立状态模型。
试用中的业务规则由模拟用户在对话中确认，不代表为其他项目推荐同一套规则。

Node 最初确认“提交下载时检查权限”，后来明确改为“开始准备时再次检查”。
这是一次需求迭代。仍在排队的任务在授权恢复后可以开始；已经取消的任务不会
复活，需要重新提交。公告编辑者也没有因此获得他人的文件权限。

实际普通录制中，任务先开始准备、后发生撤销，最终完成符合已确认规则。
“先撤销、后准备”的拒绝结果由独立的受控执行案例验证，不会为了展示想要的
结果反复重录普通业务流程。
