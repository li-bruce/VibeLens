# 播放条遮挡与资源 404：修复记录

本轮先复现并登记两个问题，再统一修改、针对性回归。沿用已有试用项目和录制，没有创建新对话。

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 播放条遮挡画布 | 公共 CSS 将播放条绝对定位在画布上方，实际覆盖 880 × 86 像素；展开步骤列表会继续占用画布 | 播放条改为独立占位的一行控件，步骤列表限高滚动；Timeline 最大化时跟随控件的实际高度避让。2D、3D 共用 |
| 页面资源 404 | 示例应用缺少默认图标，浏览器请求 `http://127.0.0.1:8925/favicon.ico` 返回 404。查看器资源正常 | 补齐应用自己的图标，通过现有静态路由提供；没有增加观察器接口，也没有修改业务函数 |
| 旧日志无法定位资源 | 只保存了控制台错误文字，没有保存请求地址 | 浏览器诊断现在保留 URL、HTTP 状态、资源类型和控制台位置，包含浏览器自动发起的图标请求 |

标准录制和 P7 的 9,882 条事件录制各通过 32 组桌面布局检查，覆盖两种尺寸、中英文、2D/3D、步骤列表和 Timeline 的展开收起，也验证了播放、定位控件与返回实时观察。原有 Timeline 12 组、变化面板 4 组回归通过，源码语法和 lint 通过。

真实应用图标已返回 200；不存在的其他资源仍返回 404，未通过屏蔽错误来使检查通过。第一次新增回归发现测试脚本等待网络诊断事件的时序问题，修正后复测通过，该失败也保留了原始结果。

原 P7 验收引用的 13 份材料哈希均未变化，已有应用的源码绑定仍为 current。查看器修复使用维护中的静态文件及原始录制验证；原来的 repair29 安装副本保持原样。本轮结果不替代先前业务与采集验收。
