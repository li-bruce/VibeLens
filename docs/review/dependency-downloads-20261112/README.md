# Viewer dependency delivery

This iteration moves unchanged third-party viewer bytes out of tracked source
and the default Skill packages. The lock keeps exact versions, sizes, hashes and
ordered CDN/GitHub URLs. Licenses, build inputs and corresponding-source access
remain available. Application execution, graph identities and native adapter
contents are unchanged.

## Checks

- `primary-download.json`: all ten actual CDN downloads match reviewed bytes.
- `github-fallback.json`: injected CDN outage, then ten actual GitHub downloads;
  every fallback matches the same pins. The GitHub requests are not mocked.
- `removal.json`: 37 tracked copies removed, 23,556,689 bytes. This changes the
  current source tree, not historical Git objects.
- `dependencies-final.log`: 13 passing failure/recovery checks, including invalid
  payloads, cache corruption, offline operation, modified assets and concurrency.
- `installation-final.log`, `distribution-retest.log`, `native-boundary.log`:
  8 installation, 4 distribution and 10 native integration checks pass.
- `source-quality.log`: syntax, lint and formatting for 188 Python and 130
  JavaScript modules pass.
- `cold-browser/`: a freshly extracted release Skill starts with no dependency
  files and an empty cache. The actual collector prepares its assets; six
  browser checks cover model views in 2D/3D, recording/replay and graph iteration.
  No browser error was recorded. Screenshots and installation results are retained.
- `example-upgrade/`: both original projects pass inspect, explicit review,
  verify, accept and check. Application source bytes are compared with the
  pre-change baseline before any prior classification is reused.
- `git-export.json`: both examples pass from a clean staged Git export after
  hydration. No source, binding or acceptance record is regenerated by this test.
- `pages-assets.json`: the static Pages build contains all ten unchanged,
  checksum-verified dependency resources.
- `package-size.json`: owned Skill files decrease from 394 to 387; the normal
  ZIP decreases from 3.63 MB to about 0.92 MB. Runtime resources remain available
  through verified downloads or the separate offline package.

## Failures and repairs

- The first dependency-test run used Windows sandbox temporary storage that was
  not writable. The fixture now uses the repository's isolated `.validation`
  directory. `dependencies-failed-temp.log` preserves the failure.
- Concurrent cache writers exposed Windows file-sharing failures during atomic
  replacement. Equal completed bytes are reused; short sharing conflicts have a
  bounded retry. `dependencies-failed-concurrent.log` preserves the reproduction.
- Package link-escape verification needs permission to create a Windows junction.
  The initial sandbox failure is in `distribution.log`; the identical test passes
  with the required filesystem capability in `distribution-retest.log`.
- The initial example verification command omitted the installed-Skill location.
  The strict integration boundary correctly refused to trust a copied runtime.
  The acceptance runner now supplies `VIBELENS_SKILL` and the native adapter path;
  `example-upgrade/delivery/inspect-attempt-1.json` preserves that failure.
- A sandboxed Git-export run could not write its redirected default cache.
  The rerun used the documented cache override within `.validation` and passed.
  `git-export-failed-cache.log` retains the failure; no permission check was bypassed.

`tools/verify.py --database` completed in one uninterrupted successful run
(`full-regression.log`, exit 0). Its final core-package smoke test confirms
`observer_modules_loaded: false`. No business assertion or mapping gate was
relaxed for this change.
