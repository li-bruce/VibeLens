# Controlled revocation diagnosis

The delivered applications were retained. Separate copies received the same controlled error: revocation targets the acting owner instead of the selected recipient. The coordinating AI seeded the fault, confirmed that original assertions failed, and sent both conversations the same symptom without revealing the cause. This is a controlled diagnostic exercise, not an organically discovered business defect or a human usability study.

- `controlled-mutation.json`: exact edits and source hashes, retained outside the worker projects.
- `native-preparation.json`: assisted copy from the native no-shim source archive, unchanged application-test pass, canonical check pass and normal change begin before mutation.
- `without-skill/`: the unassisted worker's original failure, database and browser witnesses, one-argument repair and full retest. Its report distinguishes supplied baseline evidence from checks it actually ran.
- `with-skill/`: the native assisted worker's failed tests and verify, state/rule/data facts, actual SQL-listener evidence, one-operand repair, protected assertions, complete green gate and replayed recordings. The normal change baseline was preserved.

Baseline correction: the coordinating prompt said the control copy's supplied baseline log proved 20 tests passed before mutation. That file actually recorded 12 earlier tests. The worker correctly retained this discrepancy. The original control V2 had separately reported 20 passing tests, but this local log alone does not establish that pre-mutation run. This exercise's red and green runs both executed all 20 unchanged HTTP tests; the report does not backfill a missing historical receipt.

Assisted runtime evidence initially showed zero affected rows, an unchanged shared state and a retained grant. A manually supplied request field is not proof of the driver's actual SQL binding. The worker used an independent SQL execution listener and source inspection to confirm the wrong identity. Preserve that distinction when interpreting the graph.

The paired comparison is descriptive. Applications, observability work and prior conversation lengths differ. Token totals and completion times are recorded per phase; they do not establish a general speed, cost or defect-detection advantage.
