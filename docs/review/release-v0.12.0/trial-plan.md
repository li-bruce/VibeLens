# Independent conversation trial plan

This is a plan, not a test result. Start after publishing v0.12.0. The new
conversation installs the tagged GitHub Skill into an isolated project. A parent
agent provides natural simulated user answers under the user's authorization.

Application: a small team shares files after review. Login, ownership, reviewer
permissions, recipient access and revoked links provide concrete behavior for
business, state, rule, API, source and storage inspection.

| Stage | Evidence to inspect |
| --- | --- |
| Installation | Remote tag/archive hash, Skill path, explicit invocation |
| Initial dialogue | Necessary questions, original simulated answers, mode/database choice, compact graph and verified Web link |
| Model confirmation | Independent business/state/rule views, stable identities, shared conditions, actual confirmation scope |
| First build | Native state execution, isolated observation integration, source inventory, source/comment/parameter bindings, five separate verification reports |
| Real operations | Login/rejection, upload/review/share/download/revoke, actual HTTP response, database state, invocation closure and selected values |
| Recording and views | Live graph, full and focused recording, replay/Timeline, 2D/3D, layer/facet filters, source inspection and name overlays |
| Personal controls | Prefixed conversation view control, expansion/dragging/annotations, explicit exclusions and saved configuration |
| Business iteration | Natural change request, affected graph confirmation, shared-rule dependents, implementation update and old expectation protection |
| Source refactor | Recall before changes, rebinding, new/deleted source detection, unchanged semantic identity and preferences |
| Negative checks | Missing event/capture, wrong association or unsupported definition rejected in isolated copies without changing passing expected values |
| Independence | Observation disabled/failing, exported business core and hidden Web preserve native behavior |

Use drive mode for this fresh trial; the earlier retained concept trial used
observe mode. Keep unsupported native hierarchy/concurrency semantics explicit.
The same application's notifications and two signed-in recipients provide the
async/concurrent cases without adding a separate product feature.

Extend the rows above with these concrete checks:

- Concurrent requests and asynchronous notification delivery retain their actual
  owners, parent/link evidence and lifecycle bounds.
- A real database schema change refreshes structure; reads/writes, commit and
  an applicable rollback/error are witnessed. Observer queries stay excluded.
- Timeline scrubbing, range selection, paused-step loop, execution collapse,
  single-layer display and same/cross-layer links use the recorded events.
- Viewer controls reject a missing prefix and a foreign conversation/project.
  Personal filters, placement, expansion and notes survive a source iteration;
  old-version saved recordings are cleared after the graph changes.
- Source inspection loads the complete file and highlights the bound declaration.
  Check containment in 2D/3D, negated rule labels in source/explained name modes,
  and Functions relations with both preset and explicit filters.
- Enable optional code scanning. Start recording while Code structure is selected,
  then test a focused code-root capture and historical replay; client-loaded code
  detail must be checked separately from the base API/concept graph.

Use a second receiver iteration if it fits the confirmed design. Record unsupported
features honestly rather than silently removing requested behavior or substituting
a custom validator. A finite trial complements the repository's multi-language,
database, execution and viewer regressions; it does not test every combination.

Retain the actual dialogue, screenshots, commands, build identities and
failure/repair/retest sequence. Label agent-generated demand-side replies as
simulated. General framework defects return to the maintained repository; an
already published tag is immutable.
