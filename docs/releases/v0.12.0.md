# VibeLens v0.12.0

Build connected business, state and rule models before implementation, confirm
the relevant behavior in conversation, and follow those definitions into source
and real execution. Each coding iteration checks changed meaning, implementation
bindings and independent application outcomes.

The graph now groups API entries, project structure, functions and data access
under implementation facets. Business, state, rules and storage remain available
as separate views. Hidden-layer connections retain their original path evidence;
recorded invocations retain their identities in Graph and Timeline.

This release also repairs native rule targets, transition-effect completion
requirements, guard polarity, conceptual state containment and static relations
in the Functions view. The [release review](../review/release-v0.12.0/README.md)
records the verification boundary and retained failures.
Per-event concept freshness checks also avoid repeated path resolution while
continuing to detect changed bytes, configured paths and unsafe links.

Install the complete `skills/vibelens` folder from tag **v0.12.0**, or extract
`vibelens-v0.12.0.zip`, then invoke `$vibelens` in the project conversation.
Installation remains explicit per conversation. See [usage](../usage.en.md).

The new concept-binding contract currently supports one primary native state
model and Boolean policy decisions. Native engine capabilities determine supported
hierarchy and concurrency. The external observer does not execute business rules.

## 中文

本版支持在编码前分别建立业务网、状态网和规则网，在对话中确认后关联到源码
和实际运行。每轮迭代检查模型含义、实现映射及独立的业务结果。

API、工程结构、函数和数据访问作为实现视图中的筛选项保留。隐藏图层时可以
沿原始路径呈现间接关系；Graph 与 Timeline 继续使用真实调用身份和生命周期。

同时修复规则绑定目标、副作用完成要求、否定条件、状态包含关系和函数视图的
关系筛选。检查结果与使用边界见[本版记录](../review/release-v0.12.0/README.md)。

当前概念绑定支持一个主状态模型和布尔规则判定；层次与并发能力取决于所选的
项目原生执行器。外部观察器负责采集和展示，业务仍由项目自身执行。
