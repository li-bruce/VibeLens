# VibeLens v0.11.0

Read the application graph through its business flow, API routes, documented
functions, recorded work and stored data.

- **Connected runtime context:** optional Python/Node OpenTelemetry integration
  follows asynchronous calls and linked jobs, retaining trace identity and
  selected actor, workflow and object references alongside the existing graph.
  Business/state execution and the independent observer keep their roles.
- **Shared lifecycles and Timeline:** Graph and Timeline show actual invocation
  periods, waits, calls/returns and state/value changes. Register lifecycle
  meanings already defined by the application; otherwise use neutral observed
  boundaries. Each invocation has one row per layer and folds to its business
  flow. Seek, zoom and loop ranges share the graph's replay cursor.
- **Source or explained names:** switch between source names and concise
  readable labels while identities, mappings and saved views stay fixed.
- **Closer-fitting groups:** expanded regions follow visible contents in 2D
  and 3D, including nested groups and filtered layers. Saved node positions remain.
- **Meaningful API detail:** concrete route registrations connect to their
  handlers; technical request collectors keep their separate role. Source
  docstrings and JSDoc explain mapped functions and important parameters.
  Qualified HTTP observations show request intervals and response values on
  the matching route, including routes sharing a handler.
- **Source-aware neighborhoods:** related source symbols sit closer inside
  existing type clusters, with manual positions and pinned nodes preserved.
- **Continuous development:** later changes restore confirmed decisions,
  show the affected local graph for clarification, update source/observation
  mappings and check source explanations alongside the existing business,
  state and project checks. New projects also check HTTP observation coverage
  as routes change.

Acceptance records cover [OTel and provenance](../review/otel-provenance-20261101/README.md),
[registered lifecycles](../review/declared-lifecycles/README.md),
[later-turn guidance](../review/iteration-publish-20261102/README.md) and
[the current graph-quality repairs](../review/graph-quality-20261104/README.md).
Their statuses distinguish completed validation from pending independent trials.
Dynamic connections across hidden layers remain a separate design proposal.

Install the complete `skills/vibelens` directory from **v0.11.0**, or download
**vibelens-v0.11.0.zip** from the release. In a project conversation, invoke
`$vibelens`. [Installation and usage](../usage.en.md).

## 中文

- 可选的 Python/Node OpenTelemetry 接入串联异步调用和关联作业，保留追踪标识及选定的操作者、业务和对象信息。
- 运行图与时间轴共享调用周期、等待、调用返回和状态变化；可注册程序已有的生命周期含义，每次执行按层排列并支持收起、定位、缩放和循环回放。
- 可切换源码名称与简明解释，节点、关系标识和保存的视图保持一致。
- 展开的包围圈贴合当前可见内容，支持二维、三维、嵌套和图层筛选。
- API 路由、处理函数和采集入口分别呈现；从源码注释读取函数和重要参数说明，按准确匹配的路由展示请求周期和响应值。
- 同类型节点内部参考源码位置和标识符关系排布，保留手动布局及固定点。
- 后续对话恢复已确认内容，展示受影响的局部图；同步维护业务网、状态声明、源码映射、采集和检查，并校验新增路由的观察覆盖。

详见[验收材料](../review/graph-quality-20261104/README.md)和[安装说明](../usage.zh-CN.md)。
