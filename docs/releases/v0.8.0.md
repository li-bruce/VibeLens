# VibeLens v0.8.0

Explore AI-built software from business flows to source, in a shared 2D/3D graph.

## What changes for developers

- Switch between 2D and genuine 3D; expand regions across semantic layers, reorder or hide layers, and keep saved positions and notes.
- Use typed clustering, representative 3D objects and shared straight, curved, orthogonal or bundled edges. Dragging and expansion recalculate routes in a worker.
- Follow recorded state and value changes, repeat a paused step, or choose a loop range. Source browsing opens the revision-bound complete file and highlights the mapped symbol.
- Keep business, state, API, data and optional code structure connected through existing identities and evidence.

## Maintainability

HTTP transport, graph-session admission and database comparison now have separate modules. The viewer delegates source/value, relation and step-change presentation to dedicated modules. Public imports and JSON protocols remain compatible. The bilingual source guide describes ownership and execution paths.

A shared source inventory drives pinned formatting and lint on Linux and Windows. Negative tests prove rejection of undefined bindings and duplicate keys; source-panel tests reject stale asynchronous replies. Vendor bundles and frozen evidence are excluded from rewriting and checked by hashes. Clean Git-export checks now require both examples’ original frozen approvals to remain valid, including their exact watched-file bytes. The HTTP waiting regression uses a real task barrier instead of timing-sensitive polling. The legacy delivery server now serves the complete viewer module set and correct WASM type; real browser acceptance covers both dimensions.

## Installation

Install `skills/vibelens` from the fixed `v0.8.0` tag or use `main` for subsequent updates. Invoke `$vibelens` in a project conversation, describe your application, and choose drive or observe mode during clarification. Existing projects retain their authored requirements and private view configuration.

## Validation and limits

[Release evidence](../review/release-v0.8.0/README.md) records checks, actual failures, repairs, browser screenshots and package integrity. Mapping fidelity, business expectations and state constraints remain separate reports. Synthetic large-graph measurements describe the tested machine and workload; they are not a production latency guarantee.

Database adapters cover the existing PostgreSQL, MongoDB, Redis and Neo4j fixtures. MySQL live testing, general column lineage and full formal program verification remain outside this release.
