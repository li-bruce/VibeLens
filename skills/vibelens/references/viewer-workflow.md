# Present and inspect the graph

Use English for the default interface. Set its language from the user's current conversation with `bo_design.py language --root PROJECT --locale en|zh-CN --source CONVERSATION_REFERENCE`; repeat when the conversation language changes. A user's manual Web language choice takes precedence. Keep graph IDs, source code, and user-authored labels and notes unchanged. See [interface language](interface-language.md).

Reuse the complete `assets/stategraph-viewer/` interaction. After each batch, provide the updated graph and a brief explanation of changes. Start at high-level nodes, then expand important functions, states, and values; reveal advanced details on demand. Any expanded node uses a region with its type's color. Preserve group dragging, saved layouts, typed edges, notes, core markers, search, source navigation, and replay.

Keep the canvas central. Use node/edge context menus (also Shift+F10 and selection actions), a compact visible-type legend, and labeled recording icons. Clear removes only the selected stopped recording; it leaves application data and other recordings intact. Show conversation focus directly on the graph, with no separate discussion bar. Clicking empty canvas or pressing Escape dismisses it; expired focus clears silently.

Keep source detail optional. Offer **Project structure** for directories, files and dependencies, **Local code** for a selected region, and **Code structure** for declarations and calls. Scan the engineering tree automatically from the declared project scope after coding; do not ask the user or coding agent to author a separate directory model. Files link to their declarations in the same graph. Honor display budgets and show boundary/omission information. The existing state and business graph must work when source detail is closed.

The implementation concern has three display planes: **Entry points** for registered endpoints; **Project structure** for directories, files and dependencies; **Code execution** for functions, parameters, observed actions and database operations. Start with business, states and rules, then open the required detail. These planes organize existing identities; do not duplicate a function because it is important or observed. Keep static declarations distinct from captured calls, and keep storage schemas in Data structure. Graph and Timeline use the same display classification. Migrate old implementation selections into these planes while preserving narrow facet filters, exclusions and positions.

Both 2D and true 3D use one typed graph inventory, layer visibility controls and runtime facts. Start 3D from above; keep same-layer elements on their plane and match the legend to the actual geometry. State nodes and transitions project the executable declaration, including conditions and actual hierarchy; unknown branch evidence stays unknown. Keep data operations and recorded event fields distinct from function signatures and lexical parameters; use source-context navigation without token highlighting when a field has no explicit source binding. Keep API handlers, authored function anchors, state transitions and data operations connected by explicit relations. Never join nodes by their names. In 3D, preserve semantic layers, nested containment and the owner's identity across layer projections. Source-only declarations remain static; use their explicit mapping to locate a recording owner rather than inventing execution. Retain spatial positions, pins and camera separately from 2D preferences. Preserve layer order, uniform spacing, visibility and edge shape across iterations. Compact currently visible, populated planes without empty height slots. Use recognizable solid objects in 3D with matching type colors and planar icons. Straight edges remain straight across layers; curves retain their curvature. Keep semantic type clustering within actual containment and preserve manual coordinates until Arrange. Keep 2D/3D type icons, counts, state badges and Delete-to-hide behavior equivalent. Recompute routes from current visible geometry; preserve original edge identities and report blocked paths. Playback skip/range settings and paused-step animation must never mutate recorded events or execute business commands. See [spatial graph](spatial-graph.md) for ownership, interaction and performance checks.

Provide one project development command that launches the application and its observer service together and prints both actual URLs. Keep application execution independent if observation is unavailable. The launcher must track and clean up only processes it started. Connect recording/replay to real runtime events; a design-only server has no business recording and must be labeled accordingly. Register the producer's actual scope control, bounded queue flush and health through `GraphSession.bo_bind_capture` or an equivalent integration. Test stop with queued events and focused capture before evaluating field builders; a display filter is not a capture connection. A drain failure must retain an interrupted recording and its gaps. See the [producer integration](multilanguage.md#recording-boundaries-and-capture-control). Set `require_probe_health: true` and report actual probe/data-adapter counters in normal runtime checks. Verify denied and error paths through real application entrypoints as well as normal paths; business results and mapping health are separate acceptance results. Verify both URLs, build identity, recording start/stop, and replay against a real user operation before delivery.

Every view must preserve meaningful relations. If the other endpoint is hidden, expose an explicit boundary; never invent a direct call or permission. Capture scope and replay granularity are separate. Show actual state/value changes at each step. Distinguish declarations, static derivation, and observed facts; missing or stale evidence is not current truth. See [hierarchical interaction](hierarchical-graph.md), [recording](recorded-analysis.md), and [local graphs and sharing](focus-and-sharing.md).

Respect explicit individual exclusions, including hidden groups and their descendants. “All elements” clears every exclusion while retaining layout and expansion. Folded elements remain represented by their group and counts; cross-group static relations retain their original endpoints. After a code/graph update, show only current-version recordings and leave an obsolete replay. A same-version process restart may retain recordings. Verify this across an actual reload; never reset personal views to make a new graph fit.

Separate a rule definition, relation data, and one evaluation. Do not generalize one example into all ReBAC. Read [authorization patterns](authorization-patterns.md), [rule graphs](rebac-graph.md), or [types and instances](types-rules-capture.md) when relevant.

When requested, hide the debug Web UI with `bo_web.py mode` or use the verified core export. Preserve declarations, native execution, and unified queries. Run the exported core; filenames alone do not prove removal. Personal layouts, credentials, and runtime records are private by default. Upgrades may remove unchanged superseded managed files; report conflicts for user-modified files.
